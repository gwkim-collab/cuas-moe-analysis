AIRLOCK 효과도(MOE)·시스템 분석 도구 — 문서 허브

C-UAS 요격 체계(AB-U10)의 효과도와 시스템 트레이드오프를 분석하고, 요구사항을 도출하는 도구. 이 저장소(airlock-c2)의 feat/effectiveness-analysis 브랜치에 구축. (경로는 모두 저장소 루트 기준. AIRLOCK 워크스페이스에서는 이 저장소가 components/c2/에 위치)

▶ 실행 (저장소 루트에서)

  • 원클릭: 루트의 run.cmd 더블클릭(의존성 자동 설치 후 서버+브라우저)
  • 터미널: pnpm install (최초 1회) → pnpm start (= vite --open) → http://localhost:5174/
  • 운용 화면 우상단 "효과도 분석 ▸" 버튼 / A 키로 분석 진입
  • 검증: pnpm gen:sample · pnpm exec tsc -b · pnpm test (= vitest, 59 tests)

🔒 설계 결정 / ⏳ 미정

  • 🔒 짐벌 미도입(확정) — EO 기체 고정, 획득 P_acq 상시 적용. 개선 레버는 짐벌이 아님.
  • ⏳ 표적 크기(미정) — 대상 기종 향후 결정. 인식·P_classify에 민감.

🎯 핵심 결론(요구사항 도출)

  1. 필요 탐지거리 ~2km면 충분 — 최적 2.1km에서 P_negate 정점(그 이상은 원거리 분류로 하락). 2.1km 운용만으로 +8%p.
  2. 진짜 병목은 EO 분류(P_classify) — 짐벌이 없어 표적을 좁은 화면에 넣는 조준 정밀도 σ(=√(큐²+유도²))가 관건. 목표 60%+ 달성하려면 σ≤0.3° 필요(현 σ0.5°는 상한 ~45%). σ는 겨냥이 표적에서 빗나가는 각도 오차.
  3. 표적 크기 <0.5m면 결과 지배 — 소형 가정 시 값 확정이 핵심.
  4. 악천후 취약 — 안개 0%·야간 6%. EO 의존 체계의 최대 미해결 과제(대체 센서/근접 대안 필요).

🧱 무엇을 갖췄나 (개발 경위 요약)

  • 모델: 킬체인 곱(P_detect·P_classify·P_decision·P_reach·P_kill). 물리 5층 — 레이더 탐지(R∝RCS^¼·로지스틱 Pd·누적) / 획득 P_acq(짐벌리스 Rayleigh) / Johnson 분류(EO N50: 인식·식별) / 대기감쇠(Koschmieder+Beer-Lambert) / 3D 경사거리 / 교전 기하(연속 P_reach·체공 한계).
  • UI: 6탭(교전·커버리지·트레이드·스펙역산·시나리오비교·파라미터설명; 교전 내 해석식↔몬테카를로 전환). 파라미터별 ⓘ 수식·그림·근거 3분리(이론/가정/값). 병목 진단 대시보드. 넷건/샷건 독립 입력(활성 강조).
  • 운용성: 프리셋(위협·날씨 6종)·명명 저장/불러오기·A/B 비교.
  • 입출력: CSV 왕복(근거 열 포함·Excel 호환)·JSON·리포트(MD). 값은 CSV만으로 전부 편집 가능.
  • 몬테카를로: aleatory 13변수 난수화 + 킬체인 베르누이. epistemic(값 자체)은 별도 권장.
  • 값 방침: 가상 체계라 값=가정/요구사항. "가정·입력값(미확정)" 라벨, 추측 금지. 도구 용도는 "요구사항 도출".
