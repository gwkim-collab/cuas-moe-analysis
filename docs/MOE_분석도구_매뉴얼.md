# AIRLOCK 효과도(MOE) · 시스템 분석 도구 — 사용 매뉴얼

> 대상: C-UAS 요격 체계(AB-U10)의 효과도(Measure of Effectiveness)와 시스템 트레이드오프를
> 분석하는 도구. 이 문서는 현재 구현 상태 기준의 사용·모델 설명서입니다.
>
> ⚠ **모든 기본 수치는 가정·입력값(미확정, 편집 가능)**입니다(공개 문헌·목업 근사). 확정 성능치가
> 아니며, 가상(미존재) 체계는 실측 대신 **가정/요구사항**으로 다룹니다. 이 도구의 전제는 "모든 값은 편집 가능한 입력"입니다.
>
> **확정 설계 결정**: 🔒 **짐벌 미도입**(EO는 기체 고정 · 획득 P_acq가 상시 적용). &nbsp; **미정(향후)**: 표적 크기(임계 치수).

## 1. 실행

> 경로는 모두 **저장소 루트** 기준(AIRLOCK 워크스페이스에서는 이 저장소가 `components/c2/`에 위치).

- **원클릭**: 루트의 `run.cmd` 더블클릭 → (필요 시 의존성 자동 설치) → dev 서버 + 브라우저 자동
- **터미널**: (최초 1회 `pnpm install` 후) `pnpm start` (= `vite --open`). 개발 포트 `5174` → http://localhost:5174/
- 운용 화면에서 우상단 **"효과도 분석 ▸"** 버튼 또는 키보드 **`A`** 로 진입, **`O`** 로 운용 화면 복귀
- 검증: `pnpm gen:sample`(샘플 CSV 재생성) · `pnpm exec tsc -b`(타입체크) · `pnpm test`(= vitest)

## 3. 핵심 모델 — 킬체인 곱

무력화 확률은 5개 독립 게이트의 곱입니다:

```
P_negate = P_detect × P_classify × P_decision × P_reach × P_kill
누수(leakage) = 1 − P_negate
```

가장 낮은 게이트가 **제약 단계(병목)** — 교전 효과도 상단 카드가 이를 자동 진단하고 개선 권고를 제시합니다.

### 3.0 교전은 교리로 개시된다 — 발사 개시 거리

**핵심 전제:** 이 체계는 **대응 거리가 정해져 있습니다.** 위협이 **발사 개시 거리**(기본 3 km)에 도달하면 발사합니다.
**일찍 탐지했다고 일찍 쏘지 않습니다** — 일찍 탐지하면 *여유*만 늘어납니다.

```
발사 시 위협 거리  R_launch = min( R_commit , R_detect − v_t · t_react )
필요 탐지거리      R_required = R_commit + v_t · t_react
반응 예산          t_react = 분류시간 + 결심지연 + 발사지연
분류 완료 거리     R_classify = R_launch + v_t · (결심지연 + 발사지연)
```

- **교리 지배**(탐지 충분): `R_launch = R_commit`. 탐지 성능을 더 올려도 **P_negate는 평평**하고 탐지 여유만 커집니다.
- **탐지 제약**(탐지 부족): 반응 예산이 발사 개시 거리 앞에 안 들어감 → "가능한 즉시" 발사로 후퇴.
  결과 카드·타임라인에 ⚠ 표시되고, 병목 진단이 부족분(m)을 짚습니다.

**분류 시점도 발사에서 역산**합니다 — 결심·발사 지연을 확보할 수 있는 한 **가장 늦게(=가장 가깝게, 가장 선명하게)**
분류합니다. 탐지 제약 상태에서만 `R_classify = R_detect − v_t·분류시간`으로 되돌아갑니다.

> ⚠ **모델 이력**: 이 교리 층이 생기기 전에는 발사 시점이 탐지 시점에서 파생돼(`R_launch = R_detect − v_t·t_react`),
> **레이더 성능을 올리면 분류가 더 먼 거리에서 일어나 P_negate가 오히려 떨어지는** 비직관적 거동이 있었습니다
> (최대 Pd 0.6→0.98 스윕에서 40.3%→33.6%). 지금은 그 스윕이 완전히 평평합니다.

### 3.1 물리 5층과 근거

| 단계 | 무엇 | 이론 근거 | 핵심 파라미터 |
|---|---|---|---|
| **P_detect** | 레이더 누적 탐지 | 레이더 방정식 R∝RCS^¼ · 로지스틱 Pd · 독립 스캔 누적 1−Π(1−pd) | 기준 탐지거리, **탐지거리 Pd**, 재방문 주기, RCS (최대 Pd·전이 폭은 고급) |
| **P_classify** | EO/IR 식별 | 획득 P_acq × 인식(Johnson) × 대기투과 × 분류기 상한 | 아래 참조 |
| **P_decision** | 운용자 결심 | 직렬 게이트. 선택적 인식 커플링 P_decision=신뢰도×(1−커플링·(1−인식)) | 결심 신뢰도, 결심-인식 커플링 |
| **P_reach** | 요격 도달 기하 | 등속 반경 운동학 · 여유 불확실성 정규화 Φ(여유/σ) | 순항속도, 반응예산, 요격기 도달 반경, keep-out, 체공, 여유 σ |
| **P_kill** | 이펙터 살상 | 독립 시행 이항 1−(1−p)ⁿ | 단발 Pk(net/shotgun), 사격 기회 |

### 3.2 P_classify 상세 (짐벌 없는 EO 전제)

**EO/IR 처리 단계** — 레이더가 탐지("뭔가 있다")해 준 표적을 받아 EO는 두 단계로 처리합니다:

| 단계 | 질문 | 무엇을 보나 | 파라미터 |
|---|---|---|---|
| **① 획득 (Acquisition)** | "화면에 들어왔나?" | 짐벌 없는 고정 FOV 안에 표적이 드는지 (지향 정밀도) | P_acq — 화각, 레이더 큐·요격기 지향 오차 σ |
| **② 분류 (Classification)** | "이게 뭔지?" | 들어온 표적을 Johnson 기준으로 판별 | 인식·식별 N50 |
| &nbsp;&nbsp;· 인식 (Recognition) | "위협이냐 아니냐?" | 부류 판단(드론 vs 새) | 인식 N50 (≈4.0cyc) |
| &nbsp;&nbsp;· 식별 (Identification) | "어떤 기종이냐?" | 형식 판단 | 식별 N50 (≈6.4cyc) |

여기에 **대기투과**(대비 손실)와 **분류기 상한**이 곱해집니다. 순서: **획득(들어왔나) → 분류(뭔지)**.
탐지("뭔가 있다")는 이 앞의 **레이더 단계(P_detect)**이며 EO엔 탐지 단계가 없습니다.

```
P_classify = P_acq(획득) × 인식/식별(Johnson 분류) × 대기투과 × 분류기 상한
```

**교전 기준(ROE)이 킬체인 구조를 바꿉니다** — "요구 판별 수준"에 따라 EO 게이트 적용 여부가 달라짐:

| 교전 기준 | EO 게이트 | 기본 P_negate | 오교전 위험(옵션) |
|---|---|---|---|
| **탐지**(레이더 단독) | ✗ 미적용 | **84.7%** | **16%** |
| **인식**(EO 인식) | ✓ 적용 (인식 N50) | 23.3% | 4% |
| **식별**(EO 식별) | ✓ 적용 (식별 N50) | 7.2% | 1% |

**트레이드오프가 정량화됩니다**: 느슨한 ROE(탐지)는 위협 무력화율↑(85%)이지만 **오교전(비위협 격추) 위험↑**(16%).
엄격한 ROE(식별)는 무력화율↓(14%)이나 오교전 최소(1%). 무엇을 우선할지가 ROE 선택입니다.
(오교전 위험 = 비위협 유입률 × 교전기준별 오통과율. **C2 그룹의 "오교전 위험 모델" 옵션**을 켜야 계산·표시됨. 기본 OFF.)
아래 P_classify 식은 **인식·식별** 기준일 때 적용:

```
P_classify = P_acq × 인식(Johnson) × 대기투과 T × 분류기 상한     (인식·식별 기준)
P_classify = 분류기(선언) 상한                                    (탐지 기준 — 레이더 단독)
```

- **획득 P_acq** — 짐벌이 없어 표적이 고정 FOV에 들어와야 함. 원형 가우시안 지향오차 → Rayleigh:
  `P_acq = 1 − exp(−(HFOV/2)² / (2σ²))`, `σ = √(레이더 큐 오차² + 요격기 지향 오차²)`
  → 화각을 좁히면 인식은 쉬워지나 획득이 떨어져 **최적 화각**이 존재.
- **분류 · 인식/식별(Johnson/NVESD)** — `P = nᴱ/(1+nᴱ)`, `n = 표적픽셀수/N50`, `E = 2.7+0.7n`.
  표적 픽셀 수 `N = 크기·H_px/(경사거리·HFOV_rad)`.
  EO 분류 N50: **인식(≈4.0cyc) < 식별(≈6.4cyc)** (px≈2×cycle). 탐지("뭔가 있다")는 레이더 몫(P_detect)이라
  EO N50이 없음. 교전 기준이 인식/식별이면 해당 N50이 P_classify에 쓰임.
- **대기투과 T** — Koschmieder `β=3.912/시정(km)` + Beer-Lambert `T=exp(−β·R)`.
- **경사거리(3D)** — 지상 센서 LOS = √(수평²+고도²). 탐지·인식·대기투과는 경사거리로 평가
  (고고도 표적 불리). 교전 closing 기하는 수평 반경(현재 가정).

## ★ 없는(가상) 시스템 다루기 — 실측 대신 "요구사항 도출"

레이더처럼 **아직 존재하지 않는 체계**는 값을 실측할 수 없습니다. 그래도 이 도구는 완전히 유효합니다 —
값을 **가정/요구사항**으로 두고, 오히려 **"필요 성능"을 거꾸로 도출**하는 데 씁니다.

- **레이더는 세 값이면 정의**됩니다: **기준 RCS · 기준 탐지거리 · 탐지거리 Pd**
  = *"RCS X㎡를 Y km에서 **Pd Z로** 탐지"*. 데이터시트가 실제로 주는 형태 그대로입니다.
  임의 RCS의 탐지거리는 R∝RCS^¼로 자동 환산. 나머지(최대 Pd·전이 폭)는 **고급·곡선 형태 가정값**이라
  접이식으로 숨겨져 있고 보통 손대지 않습니다.

  > ⚠ **"탐지거리"는 확률과 짝이어야 의미가 생깁니다.** 내부 로지스틱 중심(Pd 50% 지점)은 입력한 거리가
  > **아니라** 두 값에서 역산됩니다: `R_half = R_q − w·ln(P_max/p_q − 1)`.
  > 기본값 "0.01㎡ @ 3 km, Pd 0.9"는 중심 **3726 m**로 환산됩니다. 인용 거리를 그대로 곡선 중심으로 쓰면
  > 3 km에서 Pd 0.49인 **훨씬 나쁜 레이더**를 모델링하게 됩니다.
- 값의 성격은 라벨로 정직하게: **가정·입력값(미확정)** / **참고 대표값** / (있으면) 측정값.
  "실측 필요"가 아니라 "가정해서 넣는 값"입니다.

**거꾸로 쓰는 3가지:**
1. **스펙 역산** — 목표 P_negate(예 70%)를 만족하려면 특정 파라미터가 얼마여야 하는지 임계값 도출.
   예: "탐지 70% 목표 → 기준 탐지거리 최소 몇 km?" / "지향 오차는 몇 ° 이하?"
2. **트레이드 스터디** — 파라미터를 쓸며 P_negate 곡선·민감도(토네이도)로 무엇이 지배적인지 파악.
3. **병목 진단** — 교전 효과도 상단 카드가 현재 제약 단계를 짚음 → 그게 곧 "가장 급한 요구사항".

즉 **"측정값 넣는 도구"가 아니라 "요구사항 뽑는 도구"**로 쓰면 데이터가 없어도 됩니다.

> 📊 실제로 뽑은 스터디 결과(표적크기 민감도·짐벌 없는 대안·위협 케이스별 효과도)는
> **[`MOE_스터디_결과.md`](./MOE_스터디_결과.md)** 참고.

> ℹ️ **아래 예시·스터디의 P_negate 수치는 결심-인식 커플링=0(독립) 기준**으로 계산했습니다
> (연구 대상 레버를 격리하기 위함). 기본값(커플링 0.5)에서는 절대 P_negate가 약 3–4%p 낮지만,
> 최적점·임계·경향 등 결론은 동일하며, 커플링>0이면 인식 저하 효과가 오히려 증폭됩니다.

### 예시 — "필요 탐지거리" 도출 (기준 RCS 0.01㎡ 소형 FPV, 발사 개시 3 km)

**필요 탐지거리는 이제 수식으로 바로 나옵니다** — 스윕할 필요가 없습니다:

```
R_required = R_commit + v_t · t_react = 3000 + 32.8 × (6 + 10 + 4) = 3656 m
```

기본 레이더("0.01㎡ @ 3 km, Pd 0.9")의 탐지 시점은 **3704 m** → 여유 **+48 m(1.5초)**.
**교리를 간신히 충족**합니다. 조금이라도 나빠지면 탐지 제약으로 넘어갑니다.

**탐지거리 스윕** (발사 개시 3 km 고정, 커플링 0):

| 기준 탐지거리 (Pd 0.9) | 탐지 시점 | 탐지 여유 | 분류 거리 | P_classify | P_reach | P_negate |
|---|---|---|---|---|---|---|
| 1.0 km | 1703 m | −1953 m ⚠ | 1509 m | 54.9% | 74.6% | 36.5% |
| 1.2 km | 1900 m | −1756 m ⚠ | 1705 m | 53.4% | 89.5% | 42.7% |
| **1.5 km** | 2195 m | −1461 m ⚠ | 2000 m | 50.7% | 98.4% | **44.5%** |
| 2.0 km | 2687 m | −969 m ⚠ | 2492 m | 44.8% | 100% | 40.0% |
| 2.5 km | 3212 m | −444 m ⚠ | 3016 m | 37.5% | 100% | 33.4% |
| **3.0 km(기본)** | 3704 m | **+48 m** | 3460 m | 31.1% | 100% | **27.8%** |
| 3.5 km | 4196 m | +540 m | 3460 m | 31.1% | 100% | 27.8% |
| 4.0 km | 4688 m | +1032 m | 3460 m | 31.1% | 100% | 27.8% |
| 5.0 km | 5705 m | +2049 m | 3460 m | 31.1% | 100% | 27.8% |

**읽는 법 — 두 구간을 절대 섞어 읽지 마세요:**

- **3.0 km 이상 (교리 지배)**: **완전히 평평(27.8%)**. 탐지 성능을 사도 P_negate는 1%p도 안 오르고
  **여유(마진)만 삽니다.** → *탐지 요구사항은 "3.66 km 확보"이고, 그 이상은 강건성 투자지 성능 투자가 아님.*
- **3.0 km 미만 (탐지 제약)**: 표가 "레이더가 나쁠수록 P_negate가 높다"고 말합니다. **레이더를 나쁘게
  사라는 뜻이 아닙니다.** 늦은 탐지가 교전을 안쪽으로 끌어당겨 EO 분류가 쉬워지는 것뿐이고, 이는
  **3 km 발사 개시 거리 자체가 P_negate 기준으로 최적이 아니라는 신호**입니다(아래 절). 대신 여기서는
  **P_reach가 무너집니다**(1.2 km에서 89.5%, 1.0 km에서 74.6%) — 요격이 keep-out 안쪽으로 밀립니다.

**해석**: 병목은 여전히 탐지가 아니라 **EO 분류**(기본 P_classify 31.1%). 3 km 교리가 EO에 **3.46 km 인식**을
요구하기 때문입니다. → "탐지 요구사항 3.66 km, 자원은 EO에."

RCS가 다르면 R∝RCS^¼로 환산(RCS 16배 → 필요 거리 2배).

### 예시 — "발사 개시 거리" 트레이드 (교리 vs 효과도)

발사 개시 거리는 **표준(대응 거리)** 이자 이 모델에서 가장 강한 단일 레버입니다. 멀리서 쏘면 standoff를 벌지만
EO가 그만큼 먼 거리에서 인식해야 합니다. (레이더 3 km @ Pd 0.9 고정, 커플링 0)

| 발사 개시 거리 | 필요 탐지거리 | 탐지 충족 | 분류 거리 | 인식 | 요격 거리 | Keep-out 여유 | P_negate |
|---|---|---|---|---|---|---|---|
| 800 m | 1456 m | ✓ | 1262 m | 99.8% | 483 m | **−17 m** | 23.5% |
| 1000 m | 1656 m | ✓ | 1462 m | 99.4% | 604 m | 104 m | 34.4% |
| 1250 m | 1906 m | ✓ | 1711 m | 98.3% | 755 m | 255 m | 42.8% |
| **1475 m** | 2130 m | ✓ | 1936 m | 96.6% | 891 m | 391 m | **44.6% ← 최적** |
| 1750 m | 2406 m | ✓ | 2211 m | 93.6% | 1057 m | 557 m | 43.0% |
| 2000 m | 2656 m | ✓ | 2461 m | 89.7% | 1208 m | 708 m | 40.3% |
| 2500 m | 3156 m | ✓ | 2960 m | 79.7% | 1510 m | 1010 m | 34.1% |
| **3000 m(기본)** | 3656 m | ✓ | 3460 m | 68.1% | 1812 m | 1312 m | **27.8%** |
| 3500 m | 4156 m | ✗ 부족 | 3508 m | 66.9% | 1841 m | 1341 m | 27.2% |

- **P_negate 최적 ≈ 1.5 km (44.6%)**. 3 km 교리는 여기서 **−16.8%p**를 지불합니다.
- 1 km 아래로 내려가면 요격점이 keep-out(500 m)에 붙어 **P_reach가 무너집니다** — 내부 최적이 존재하는 이유.
- **그럼 1.5 km로 바꿔야 하나? 아닙니다.** P_negate는 "무력화했나"만 셉니다. 3 km를 고르는 이유
  — 파편·낙하물 standoff, 2차 교전 기회, keep-out 여유 1312 m — 는 **이 지표 바깥**에 있습니다.
  이 표는 "3 km 교리의 **가격표**가 −16.8%p"라는 사실을 보여주는 것이고, 그 값을 지불할지는 교리 판단입니다.

**3 km를 유지하려면 EO에 무엇을 요구해야 하나** (합성 지향오차 σ 스윕, 발사 개시 3 km 고정):

| 지향오차 σ | P_acq | 인식 | P_negate |
|---|---|---|---|
| 0.5°(기본) | 67.5% | 68.1% | 27.8% |
| 0.4° | 82.8% | 68.1% | 34.0% |
| 0.3° | 95.6% | 68.1% | 39.3% |
| 0.2° | 99.9% | 68.1% | 41.1% |
| 0.1° | 100% | 68.1% | **41.1% ← 상한** |

⚠ **지향 정밀도를 완벽하게 만들어도 3 km 교리에서는 41.1%가 상한**입니다. 인식확률이 68.1%에 고정돼 있기
때문 — 3.46 km에서 표적 픽셀이 7.4 px뿐입니다. **3 km 교리로 40%+를 넘기려면 지향(σ)만으로는 부족하고,
해상도·화각·표적크기 쪽 픽셀 예산을 같이 올려야 합니다.**

### 예시 — "EO 분류 필요 스펙" 도출 (지향오차 · 화각)

기본 시나리오의 병목은 EO 분류(P_classify 31.1%, P_acq 67.5%, 인식 68.1%, σ=0.50°).
3 km 교리가 분류를 3.46 km로 밀어놓은 상태에서, 무엇을 얼마나 개선해야 하나? (커플링 0)

**① 요격기 지향오차 — P_acq 경로 (단조, 큐 오차 0.3° 고정):**

| 지향오차 | 합성 σ | P_acq | P_classify | P_negate |
|---|---|---|---|---|
| 0.1° | 0.32° | 94% | 43.3% | 38.6% |
| 0.2° | 0.36° | 89% | 40.8% | 36.4% |
| 0.4°(기본) | 0.50° | 68% | 31.1% | 27.8% |
| 0.6° | 0.67° | 46% | 21.4% | 19.1% |
| 0.9° | 0.95° | 27% | 12.4% | 11.0% |

스펙 역산(목표 → 허용 **최대** 지향오차): 30% → **≤0.35°** · 35% → **≤0.23°** · **40% → 달성 불가**.
⚠ 지향오차를 0으로 만들어도(P_acq=100%) **3 km 교리에서는 41.1%가 천장**입니다 — 인식이 68.1%에 묶여 있어서.

**② 화각 — P_acq ↔ 인식 상충 (비단조):**

| 화각 | P_acq | 인식 | 표적 픽셀 | P_negate |
|---|---|---|---|---|
| 0.8° | 27% | 97% | 13.9 px | 16.1% |
| 1.0° | 39% | 92% | 11.1 px | 21.9% |
| 1.2° | 51% | 84% | 9.3 px | 26.0% |
| **1.46°** | 66% | 70% | 7.6 px | **27.8% ← 최적** |
| 1.5°(기본) | 68% | 68% | 7.4 px | 27.8% |
| 2.0° | 86% | 44% | 5.6 px | 22.8% |
| 2.5° | 96% | 28% | 4.5 px | 16.0% |

기본 1.5°가 사실상 최적(1.46°) → **화각 튜닝 여지 없음(+0.0%p)**. 화각은 P_acq와 인식을 맞바꿀 뿐,
**픽셀 총량을 늘리지 못하기 때문**입니다.

**③ 해상도 — 픽셀 예산을 실제로 늘리는 유일한 레버:**

| 가로 해상도 | 표적 픽셀 | 인식 | P_negate |
|---|---|---|---|
| 1920 px(기본) | 7.4 px | 68% | 27.8% |
| 2560 px | 9.9 px | 87% | 35.6% |
| 3840 px | 14.8 px | 98% | 40.1% |
| 5120 px | 19.8 px | 100% | 40.7% |
| 7680 px | 29.7 px | 100% | **40.8% ← 포화** |

**결론(요구사항) — 짐벌 미도입(확정) + 발사 개시 3 km 전제:**

이전 판의 결론("지향 정밀도가 유일한 핵심 레버")은 **3 km 교리에서는 더 이상 충분하지 않습니다.**
지향(σ)과 픽셀(해상도)은 **각각 독립적인 천장**을 만듭니다:

- **σ만 개선** → P_acq→100%, 인식 68% 고정 → **천장 41.1%**
- **해상도만 개선** → 인식→100%, P_acq 67.5% 고정 → **천장 40.8%**
- **둘 다 필요** — 40%대 초반을 넘으려면 σ≤0.3° **와** 해상도 상향을 **동시에** 가야 합니다.

세 번째 선택지가 **발사 개시 거리를 당기는 것**입니다(1.48 km → 44.6%, 하드웨어 변경 없음).
standoff와 맞바꾸는 교리 결정이므로, EO 하드웨어 투자와 **같은 저울에 올려놓고 비교**해야 합니다.

- **교전 효과도**: P_negate/누수 + 교전 성립, 제약 단계 카드, 킬체인 막대, EO/IR 인식·획득 readout, 교전 기하 타임라인.

  - **탐지 거리(사양 Pd 기준)** = 입력한 인용 거리를 위협 RCS로 환산한 값 / **Pd 50% 거리** = 내부 곡선 중심(역산값).
  - **필요 탐지거리 · 탐지 여유** = 교리 충족 판정. 여유가 음수면 ⚠ 탐지 제약이며 병목 진단이 부족분을 짚습니다.

- **트레이드 스터디**: 파라미터 vs P_negate 1D/2D 스윕 + 민감도 토네이도.
- **스펙 역산**: 목표 P_negate를 만족하는 파라미터 임계값 역산.
- **시나리오 비교**: 현재(A) vs 프리셋/저장본(B) 지표 나란히 + Δ(개선=초록·악화=빨강).
- **파라미터 설명**: 전 파라미터 의미·값 출처 표 + 행별 "수식·그림".

**입력 검증** — 좌측 패널 상단에 배너가 뜨면 그 결과는 믿지 마세요. 🔴 **오류**는 물리적으로 불가능한 값
(확률 >1, 음수 거리 등)으로, 모델이 강제 클램프해 계산하므로 결과가 무의미합니다. 🟠 **경고**는 계산은 되지만
의도와 다를 수 있는 조합입니다. `↺ 범위로 자동 수정`으로 한 번에 되돌릴 수 있습니다 — FAQ Q13.

## 8. 몬테카를로 설계 — 어떤 변수에 오차가 들어가나

두 종류의 불확실성이 있습니다.

### 8.0 시행수 — 얼마나 돌려야 하나 (기본 10,000)

MC 1 시행은 **해석식 `computeMoe` 1회**(탐지 스윕 168 look + 닫힌 해 공식 십여 개)라 **약 0.02 ms**입니다.
물리 시뮬레이션이 아니라 산수라서 매우 빠릅니다 — 결과가 순식간에 나오는 건 정상입니다.

| 시행수 | 소요(참고) | 95% CI 반폭 |
|---|---|---|
| 1,000 | 21 ms | ±2.61%p |
| 3,000 | 63 ms | ±1.50%p |
| **10,000(기본)** | **204 ms** | **±0.82%p** |
| 100,000 | 2.0 s | ±0.26%p |

- CI 폭은 **1/√n**로 줄어듭니다. 시행수를 4배 늘려야 오차가 절반이 됩니다.
- **기본이 10,000인 이유**: 이 도구는 시나리오 간 **몇 %p 차이**를 비교하는 데 씁니다.
  3,000(±1.5%p)에서는 그 차이가 표본오차에 묻힙니다. CI 반폭이 ±1%p를 넘으면 화면에 경고가 뜹니다.
- **상한 200,000** — MC는 렌더 스레드에서 동기로 돌기 때문에, 시행수가 크면 그동안 화면이 멈춥니다.
- 같은 seed면 결과가 **완전히 재현**됩니다(mulberry32 시드 RNG). seed를 바꿔 흔들림 폭을 눈으로 확인하세요.

⚠ **정밀도 착시 주의** — CI는 **표본오차만** 나타냅니다. 100,000회로 ±0.26%p를 만들어도
입력값 대부분이 가정·플레이스홀더인 사실은 그대로입니다(§8.3). **시행수를 늘려도 그 불확실성은 줄지 않습니다.**

### 8.2 미반영 → 반영으로의 차이 (정확히)

변수를 `sampleScenario`에 배선하면 매 시행 새 값을 뽑습니다. 이때 두 가지가 달라집니다:
- **시행별 P_negate 히스토그램 폭** ↑ (입력 변동이 분포에 나타남)
- **평균(mean) 이동** — 모델이 비선형/비대칭이면 평균 자체가 움직임.
  예: 고도(경사거리 볼록)·표적크기 변동은 불리한 쪽 페널티가 더 가팔라 **평균 P_negate를 끌어내림**
  (실측 예: 후보 반영 시 평균 37%→33%).

> 주의 — 도구의 **`ci95`는 "무력화 *분율*"의 몬테카를로 표본오차**(≈1.96·√(p(1−p)/n))로,
> 주로 **시행 수 n**이 지배합니다. 입력 변동을 늘려도 이 분율 CI 폭은 크게 안 변합니다
> (그건 시행별 P_negate **히스토그램**과 **평균**에 나타남). CI를 좁히려면 시행 수를 늘리세요(§8.0).

위 표는 현재 반영된 aleatory 입력 전체입니다. 미반영이면 고정값이라 그 변수의 변동이 분포·평균에 0 기여(과신).

### 8.3 Epistemic(값 자체를 모름 — 플레이스홀더) — 현재 미반영, 실측 전까지 사실상 지배적

- **단발 Pk**, **N50(탐지/인식/식별)**, **기준 탐지거리**, **결심 신뢰도**, **분류기 상한**
- 이 값들은 "입력 필요" 상태라 불확실성이 큼. 정식 MC 설계 시 이들에 대한 **파라미터 사전분포**를 별도로 두는 것을 권장(aleatory와 분리).

### 8.4 주의 — 이중 계산

`여유 σ`(reach_margin_sigma_m)는 해석식에서 P_reach를 이미 연속화합니다. MC에서는 속도·타이밍
입력을 난수화해 여유가 또 흔들리므로 **부분 이중 계산**이 됩니다. 정식 MC에서는 (a) 여유 σ=0으로 두고
입력 난수가 도달 변동을 만들게 하거나, (b) σ를 "모델 외 잔여 지터"로만 해석하도록 정하세요.

## 10. 설계 결정·한계·가정

**확정 설계 결정**
- 🔒 **짐벌 미도입** — EO는 기체 고정. 획득 P_acq(고정 FOV)가 상시 적용되며, 지향 정밀도는 레이더 큐+유도로만 확보. (개선 레버가 "짐벌"이 아님을 전제로 요구사항 도출)

**미정(향후 결정)**
- ⏳ **표적 크기(임계 치수)** — 대상 기종 미정. 값은 가정(참고 0.35m)이며, 인식·P_classify에 민감하므로 확정 시 재평가 필요.

**모델 한계·가정**
- **교전은 교리(발사 개시 거리)로 개시**되고 탐지 시점으로 개시되지 않음. 분류 시점도 발사에서 역산 —
  즉 "타임라인이 허용하는 한 가장 가깝게 분류한다"를 가정. 실제로 조기 분류를 강제하는 ROE/절차가 있다면 낙관적.
- **탐지 독립 look 가정** — 누적 P_det = 1−Π(1−pd)는 스캔 간 완전 독립을 전제. 실제로는 Swerling 변동 상관,
  지형 차폐·다중경로, 저고도 클러터 노치, 트래커 M-of-N 확정 요구가 있어 **유효 독립 look 수가 훨씬 적습니다.**
  기본값에서 P_detect가 100%로 포화하는 것은 이 가정의 결과이며 **낙관적**입니다 — FAQ Q10 참조.
- 교전 closing 기하는 수평 반경(고도는 센싱에만 반영).
- 방위 회전대칭(방위별 차이 없음) — 섹터별 keep-out/지형은 미반영.
- 단일 표적(스웜 미지원).
- P_decision–인식 커플링은 파라미터로 조절(기본 0.5). 0=독립. 인식이 P_classify도 게이팅하므로 부분 이중계산 가능 — "인간 판단 추가 민감도"로 해석.
- 넷건/샷건은 택일 페이로드(동시 레이어 미지원).

## 11. 자주 헷갈리는 점 (FAQ)

**Q1. P_negate가 킬체인 각 단계 확률보다 낮은데 정상인가?**
정상입니다. P_negate는 5단계의 **곱**입니다. 1 이하 값을 여러 개 곱하면 어떤 개별 값보다 작아집니다.
기본값: `100% × 31.1% × 82.3% × 100% × 91% = 23.3%`. 가장 낮은 게이트(P_classify 31.1%)보다도 낮은 건
뒤의 P_decision(82.3%)·P_kill(91%)이 또 곱해지기 때문. → "모든 단계 통과 확률 ≤ 한 단계 통과 확률".

**Q2. Pd 전이 폭을 바꿔도 결과가 거의 안 변한다?**
전이 폭은 탐지 Pd 곡선의 경계 완만도에만 작용합니다. 기본 시나리오는 누적 탐지가 이미 **P_detect≈100%로 포화**라
체감이 거의 없습니다. 큰 값(1000·2000m)으로 바꾸면 탐지 시점(detect_at)이 안쪽으로 이동 → 분류 거리→인식 경로로
소폭(+1%p)만 나타납니다. 탐지가 아슬아슬한 설계에서만 크게 작동.

**Q3. 인식/식별 N50을 바꿔도 결과가 안 변할 때가 있다?**
EO N50은 인식·식별 2개이며, "요구 판별 수준(교전 기준)"에 해당하는 것만 P_classify에 쓰입니다. 기본은 **인식**이라
인식 N50만 활성(식별 N50 무변). 식별 N50을 반영하려면 교전 기준을 **식별**로 바꾸세요. 교전 기준이 **탐지(레이더
단독)**면 EO를 안 써서 두 N50 모두 결과에 영향이 없고, EO 표시값은 "—"로 나옵니다. — Q7 참조.
(참고: "탐지=뭔가 있다"는 레이더 몫(P_detect), "분류=이게 뭔지"는 EO 몫(P_classify: 인식/식별).)

**Q7. 교전 기준(요구 판별 수준)이 결과를 크게 바꾼다?**
네. 이건 킬체인 **구조**를 바꿉니다. **탐지**(레이더 단독)는 EO 게이트를 아예 빼서 P_negate가 높지만(예 84.7%)
오교전 위험↑. **인식**(23.3%)·**식별**(7.2%)은 EO 게이트를 적용(식별이 더 엄격). 느슨할수록 무력화율↑·안전성↓의
트레이드오프이며, **오교전(비위협 격추) 위험**은 C2 그룹의 "오교전 위험 모델" 옵션을 켜면 정량화됩니다
(탐지 16% / 인식 4% / 식별 1%). P_negate와 별개 지표입니다.

**Q4. "요격기 도달 반경"이 넷건 사거리인가?**
아닙니다. **요격기 도달 반경**(기본 2500m)은 요격 드론(AB-U10)이 발사대에서 날아가 도달하는 **작전 반경**입니다.
**넷건 사거리(~25m)**는 도달 후 표적에 붙어 넷을 쏘는 **종말 발사 거리**(별개, 현재 P_kill에 암묵 포함).

**Q5. 넷건·샷건 Pk가 둘 다 있는데 왜 하나만 반영되나?**
**페이로드(택일)**가 선택한 쪽의 Pk만 P_kill에 들어갑니다. 패널에서 활성 무기는 강조, 비활성은 흐리게 표시됩니다.

**Q6. 기본 P_negate가 23.3%인 이유?**
게이트 곱(Q1) + **결심-인식 커플링(기본 0.5)**(P_decision 98%→82.3%) + **발사 개시 거리 3 km 교리**입니다.
3 km에서 쏘려면 EO가 **3.46 km에서 인식**해야 하고, 거기선 표적 픽셀이 7.4 px뿐이라 P_classify가 31.1%로 눌립니다.
커플링을 **0(독립)**으로 두면 27.8%. 발사 개시 거리를 최적점(≈1.5 km)으로 당기면 44.6%까지 오릅니다
(§발사 개시 거리 트레이드 — 그 차이가 3 km 교리의 가격표).

**Q8. P_acq(획득 확률)는 입력인가?**
아닙니다. **계산되는 값**입니다. P_acq = 1−exp(−(HFOV/2)²/(2σ²)), σ=√(큐오차²+지향오차²) — 즉 **화각·큐
오차·지향 오차(입력)로부터 산출**됩니다. 좌측 패널 = 입력값(편집 가능), 우측 결과카드 = 계산값(P_acq·인식확률·
P_classify 등, 읽기 전용). P_acq는 좌측에 없고 우측에만 나옵니다.

**Q9. "탐지"와 "분류"는 뭐가 다른가?**
- **탐지(detection) = "뭔가 있다"** → **레이더** 담당 (P_detect).
- **분류(classification) = "이게 뭔지"** → **EO/IR** 담당 (P_classify). EO는 ①**획득**(화면에 들어왔나, P_acq)
  → ②**분류**(인식="위협이냐"·식별="어떤 기종"). EO엔 탐지 단계가 없습니다(탐지는 레이더 몫).

**Q10. P_detect가 100%로 나오는데 정상인가?**
정상이고, **모델 구조상 그렇게 됩니다.** 누적 탐지 `P_det = 1−Π(1−pd_i)`는 접근 트랙 전체에 걸쳐 **독립 look을
곱해 지우는** 형태입니다. 기본값에선 진입 6 km→keep-out 500 m 구간을 32.8 m 간격(속도 32.8 m/s × 재방문 1.0 s)으로
샘플해 **look이 168회** 쌓이고, `Π(1−pd)`가 천문학적으로 작아져 P_det = 1.000이 됩니다.

단일 파라미터로는 잘 안 떨어집니다 — 최대 Pd를 0.5로 낮춰도, 탐지거리를 절반으로 줄여도, RCS를 1/10로 해도
여전히 100%입니다. **지배 레버는 look 수 = 재방문 주기 × 표적 속도**뿐입니다(재방문 20 s·속도 150 m/s면 급락).

⚠ **해석 주의**: 100%는 "탐지가 완벽하다"가 아니라 **"이 가정 아래선 탐지가 병목이 아니다"**로 읽으세요.
독립 look 가정이 낙관적입니다(§10 모델 한계). 그리고 P_detect가 100%여도 **탐지가 늦으면** 여전히 문제입니다 —
그건 P_detect가 아니라 **탐지 여유(필요 탐지거리 대비)**가 잡아냅니다. Q11 참조.

**Q11. 레이더 성능(탐지거리·최대 Pd)을 올려도 P_negate가 안 변한다?**
정상입니다. **교전이 교리로 개시**되기 때문입니다(§3.0). 탐지 여유가 이미 양수(교리 지배)라면, 탐지를 더 잘해도
발사 시점·분류 시점·요격 지점이 **하나도 안 움직입니다** — 늘어나는 건 탐지 여유뿐입니다.

레이더 성능이 P_negate를 움직이는 구간은 **탐지 여유가 음수일 때(⚠ 탐지 제약)**뿐입니다. 결과 카드의
"탐지 여유"를 먼저 보세요. 양수면 레이더는 이미 충분하고, 자원은 EO 쪽에 써야 합니다.

> 참고: 예전(교리 층 도입 전) 모델에서는 탐지 성능을 올리면 P_negate가 **떨어졌습니다**. 발사가 탐지에
> 묶여 있어 분류가 더 먼 거리로 밀렸기 때문입니다. 지금은 그 인공적 역행이 사라졌습니다.

**Q12. 데이터시트에 "Pd 0.9 @ 3 km"라고 있으면 어떻게 넣나?**
그대로 넣으면 됩니다 — **기준 탐지거리 = 3000, 탐지거리 Pd = 0.9**. 도구가 내부 로지스틱 중심을
`R_half = R_q − w·ln(P_max/p_q − 1) = 3726 m`로 역산합니다.

⚠ **하지 말아야 할 것**: 예전처럼 기준 탐지거리에 3000만 넣고 확률을 무시하는 것. 그러면 3 km가 **Pd 50% 지점**으로
해석돼 실제보다 나쁜 레이더가 됩니다. "탐지거리"는 항상 **확률과 짝**으로 말해야 의미가 생깁니다.
(최대 Pd·전이 폭은 고급 접이식에 있으며, **탐지거리 Pd보다 최대 Pd가 커야** 합니다.)

**Q13. 확률에 95를 넣었더니 P_negate가 이상하게 높게 나온다?**
**확률은 0~1입니다. 95는 95%가 아니라 "9500%"로 읽힙니다.** 모델은 모든 게이트를 `clamp(x, 0, 1)` 하므로
95는 조용히 **1.0(=100%)**이 되고, 그 단계가 **아예 없는 것처럼** 동작합니다. 예: 분류기 상한에 95를 넣으면
P_classify가 31.1% → **100%**가 되어 P_negate가 23.3% → **74.9%**로 튑니다.

지금은 이런 값이 들어오면 **좌측 패널과 결과 상단에 빨간 배너**가 뜨고 해당 필드가 붉게 표시됩니다.
`↺ 범위로 자동 수정` 버튼으로 전부 유효 범위로 되돌릴 수 있습니다. CSV 불러오기도 범위 밖 값을 보고합니다
(엑셀에서 0.95가 95로 바뀌는 사고가 가장 흔합니다).

검사 항목은 두 가지입니다:
- **범위 검사** — 파라미터별 물리적 유효 범위(확률 0~1, 거리 ≥0, 방위 0~360°, 정수여야 하는 값 등)
- **교차 검사** — 값 하나만으론 알 수 없는 관계: `탐지거리 Pd < 최대 Pd`, `발사 개시 거리 > keep-out`,
  `발사대 거리 < 발사 개시 거리`, `인식 N50 ≤ 식별 N50`, `진입 거리 ≥ 필요 탐지거리` 등
  (마지막 둘은 **경고** — 계산은 되지만 의도와 다를 수 있다는 뜻)

**Q14. 몬테카를로 "누수 원인"에서 탐지가 0이고 살상이 이상하게 크다?**
두 가지를 나눠서 봐야 합니다.

**① 탐지 0은 정상입니다.** 이 패널은 킬체인 순서(탐지→분류→결심→도달→살상)로 판정해 **처음 실패한 단계만
1회** 집계합니다. P_detect가 100%면 탐지는 절대 첫 실패가 될 수 없으므로 항상 0입니다. **0 = "그 단계의 확률이
0"이 아니라 "그 단계가 첫 실패인 적이 없다"** 입니다. 같은 이유로 앞 단계가 크게 깎으면 뒷 단계 숫자는
자동으로 작아집니다(도달 0도 같은 이유).

**② 살상이 크게 나온다면 대부분 앞 단계가 클램프된 상태입니다.** 기본값에서는 살상 첫 실패가 전체의 ~3%인데,
분류기 상한에 95를 넣어 P_classify가 100%로 클램프되면 분류에서 아무도 안 걸러져 살상 실패가 **~10%(누수의 36%)**로
튑니다. 즉 "살상이 이상하다"는 **살상 파라미터 문제가 아니라 앞 단계 입력 오류의 증상**입니다 — Q13의 배너를 먼저 보세요.

> 🔧 관련 수정: 이전에는 MC가 사격 기회 수를 `max(0, …)`로 샘플링해 약 1.6%의 시행이 **0발**이 되고
> 그 시행의 P_kill이 0이 됐습니다. 요격기가 도달했는데 0발을 쏘는 건 물리적 결과가 아니므로 하한을 1발로 고쳤습니다.
