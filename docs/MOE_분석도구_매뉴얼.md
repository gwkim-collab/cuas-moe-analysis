# AIRLOCK 효과도(MOE) · 시스템 분석 도구 — 사용 매뉴얼

> 대상: C-UAS 요격 체계(AB-U10)의 효과도(Measure of Effectiveness)와 시스템 트레이드오프를
> 분석하는 도구. 이 문서는 현재 구현 상태 기준의 사용·모델 설명서입니다.
>
> ⚠ **모든 기본 수치는 가정·입력값(미확정, 편집 가능)**입니다(공개 문헌·목업 근사). 확정 성능치가
> 아니며, 가상(미존재) 체계는 실측 대신 **가정/요구사항**으로 다룹니다. 이 도구의 전제는 "모든 값은 편집 가능한 입력"입니다.
>
> **확정 설계 결정**: 🔒 **짐벌 미도입**(EO는 기체 고정 · 획득 P_acq가 상시 적용). &nbsp; **미정(향후)**: 표적 크기(임계 치수).

## 3. 핵심 모델 — 킬체인 곱

무력화 확률은 5개 독립 게이트의 곱입니다:

```
P_negate = P_detect × P_classify × P_decision × P_reach × P_kill
누수(leakage) = 1 − P_negate
```

가장 낮은 게이트가 **제약 단계(병목)** — 교전 효과도 상단 카드가 이를 자동 진단하고 개선 권고를 제시합니다.

### 3.1 물리 5층과 근거

| 단계 | 무엇 | 이론 근거 | 핵심 파라미터 |
|---|---|---|---|
| **P_detect** | 레이더 누적 탐지 | 레이더 방정식 R∝RCS^¼ · 로지스틱 Pd · 독립 스캔 누적 1−Π(1−pd) | 기준 탐지거리, 최대 Pd, 전이 폭, 재방문 주기, RCS |
| **P_classify** | EO/IR 식별 | 획득 P_acq × 인식(Johnson) × 대기투과 × 분류기 상한 | 아래 참조 |
| **P_decision** | 운용자 결심 | 직렬 게이트. 선택적 인식 커플링 P_decision=신뢰도×(1−커플링·(1−인식)) | 결심 신뢰도, 결심-인식 커플링 |
| **P_reach** | 요격 도달 기하 | 등속 반경 운동학 · 여유 불확실성 정규화 Φ(여유/σ) | 순항속도, 반응예산, 최대교전거리, keep-out, 체공, 여유 σ |
| **P_kill** | 이펙터 살상 | 독립 시행 이항 1−(1−p)ⁿ | 단발 Pk(net/shotgun), 사격 기회 |

### 3.2 P_classify 상세 (짐벌 없는 EO 전제)

```
P_classify = P_acq × 인식(Johnson) × 대기투과 T × 분류기 상한
```

- **획득 P_acq** — 짐벌이 없어 표적이 고정 FOV에 들어와야 함. 원형 가우시안 지향오차 → Rayleigh:
  `P_acq = 1 − exp(−(HFOV/2)² / (2σ²))`, `σ = √(레이더 큐 오차² + 요격기 지향 오차²)`
  → 화각을 좁히면 인식은 쉬워지나 획득이 떨어져 **최적 화각**이 존재.
- **인식(Johnson/NVESD)** — `P = nᴱ/(1+nᴱ)`, `n = 표적픽셀수/N50`, `E = 2.7+0.7n`.
  표적 픽셀 수 `N = 크기·H_px/(경사거리·HFOV_rad)`.
  판별 수준별 N50 분리: **탐지(≈1.0cyc) < 인식(≈4.0cyc) < 식별(≈6.4cyc)** (px≈2×cycle).
  "요구 판별 수준" 선택이 P_classify에 쓰이는 N50을 결정.
- **대기투과 T** — Koschmieder `β=3.912/시정(km)` + Beer-Lambert `T=exp(−β·R)`.
- **경사거리(3D)** — 지상 센서 LOS = √(수평²+고도²). 탐지·인식·대기투과는 경사거리로 평가
  (고고도 표적 불리). 교전 closing 기하는 수평 반경(현재 가정).

## ★ 없는(가상) 시스템 다루기 — 실측 대신 "요구사항 도출"

레이더처럼 **아직 존재하지 않는 체계**는 값을 실측할 수 없습니다. 그래도 이 도구는 완전히 유효합니다 —
값을 **가정/요구사항**으로 두고, 오히려 **"필요 성능"을 거꾸로 도출**하는 데 씁니다.

- **레이더는 두 값이면 정의**됩니다: **기준 RCS · 기준 탐지거리** = *"RCS X㎡를 Y km에서 탐지"*.
  임의 RCS의 탐지거리는 R∝RCS^¼로 자동 환산. 나머지 레이더 파라미터(Pd 상한·전이 폭·재방문)는
  **곡선 형태 가정값**이라 보통 손대지 않아도 됩니다.
- 값의 성격은 라벨로 정직하게: **가정·입력값(미확정)** / **참고 대표값** / (있으면) 측정값.
  "실측 필요"가 아니라 "가정해서 넣는 값"입니다.

**거꾸로 쓰는 3가지:**
1. **스펙 역산** — 목표 P_negate(예 70%)를 만족하려면 특정 파라미터가 얼마여야 하는지 임계값 도출.
   예: "탐지 70% 목표 → 기준 탐지거리 최소 몇 km?" / "지향 오차는 몇 ° 이하?"
2. **트레이드 스터디** — 파라미터를 쓸며 P_negate 곡선·민감도(토네이도)로 무엇이 지배적인지 파악.
3. **병목 진단** — 교전 효과도 상단 카드가 현재 제약 단계를 짚음 → 그게 곧 "가장 급한 요구사항".

즉 **"측정값 넣는 도구"가 아니라 "요구사항 뽑는 도구"**로 쓰면 데이터가 없어도 됩니다.

> 📊 실제로 뽑은 스터디 결과(표적크기 민감도·짐벌 없는 대안·위협 케이스별 효과도)는
> **[`MOE_스터디_결과.md`](./MOE_스터디_결과.md)** 참고.

### 예시 — "필요 탐지거리" 도출 (기준 RCS 0.01㎡ 소형 FPV, 기본 시나리오)

**스펙 역산(목표 P_negate → 최소 탐지거리):**

| 목표 P_negate | 필요 탐지거리(최소) |
|---|---|
| 20% | ≥ 1.43 km |
| 30% | ≥ 1.61 km |
| 35% | ≥ 1.71 km |
| 40% | ≥ 1.83 km |

- **성립 하한 ≈ 1.2 km** — 그 미만이면 P_reach=0(너무 늦게 탐지 → 요격 시간 없음).

**⚠ 비직관적 결과 — "무조건 멀리 탐지 = 좋다"가 아님.** 탐지거리 스윕:

| 탐지거리 | P_reach | P_negate |
|---|---|---|
| 1.5 km | 47% | 23.7% |
| **2.0 km** | 93% | **43.9% ← 최적** |
| 3.0 km(기본) | 100% | 36.5% |
| 4.0+ km | 100% | 36.1% |

탐지거리가 길면 분류(classify)가 *먼 거리*에서 일어나 픽셀↓·인식↓ → P_classify 하락.
탐지↑의 이득(반응시간)과 손해(원거리 분류)가 상충해 **최적 탐지거리 ≈ 2 km**.

**해석**: 이 체계의 병목은 탐지가 아니라 **EO 분류**(기본 P_classify 41%). 탐지거리를 더 키우기보다
**화각·지향오차·시정 등 EO 분류 스펙 개선**이 효과적. → "탐지거리 요구사항 ~2 km면 충분, 자원은 EO에."

**주의(방법론)**: 스펙 역산 solver는 증가 관계를 가정해 **하한(최소)**만 반환합니다. 위처럼 관계가
**비단조(2 km 정점)**면 실제 만족 구간은 창(예: 40%는 ~1.8–2.4 km)입니다 — 트레이드 스터디 스윕으로 확인하세요.
RCS가 다르면 R∝RCS^¼로 환산(RCS 16배 → 필요 거리 2배).

### 예시 — "EO 분류 필요 스펙" 도출 (지향오차 · 화각)

기본 시나리오의 병목은 EO 분류(P_classify 41%, P_acq 67.5%, σ=0.50°). 이걸 개선하려면 무엇이 얼마여야 하나?

**① 요격기 지향오차 (단조 — 낮을수록 좋음):**

| 지향오차 | P_acq | P_classify | P_negate |
|---|---|---|---|
| 0.1° | 94% | 57.0% | 50.9% |
| 0.2° | 89% | 53.7% | 47.9% |
| 0.4°(기본) | 68% | 41.0% | 36.5% |
| 0.6° | 46% | 28.2% | 25.1% |
| 0.9° | 27% | 16.3% | 14.5% |

스펙 역산(목표 P_negate → 허용 **최대** 지향오차): 40% → **≤0.35°** · 45% → **≤0.26°** · 50% → **≤0.14°**.
→ 의미 있는 개선은 **sub-0.3° 지향 정밀도**를 요구 → 사실상 **짐벌/정밀 유도** 필요.

**② 화각 (비단조 — 최적 존재):**

| 화각 | P_acq | 인식 | P_negate |
|---|---|---|---|
| 1.0° | 39% | 97% | 24.8% |
| 1.5°(기본) | 68% | 84% | 36.5% |
| **1.7°** | 76% | 76% | **37.3% ← 최적** |
| 2.0° | 86% | 63% | 35.0% |
| 2.5° | 96% | 44% | 26.9% |

기본 1.5°는 이미 최적(1.7°) 근처 → **화각 튜닝 여지는 작음**(+0.8%p). 35% 만족 창 ≈ 1.4–1.9°.

**결론(요구사항) — 짐벌 미도입(확정) 전제**: EO 분류 개선의 핵심 레버는 화각이 아니라 **지향 정밀도**.
합성 지향오차 σ=√(큐²+지향²)를 **sub-0.3°**로 낮추는 것이 목표 40%+ 달성의 관건입니다.
**그런데 짐벌 미도입이 확정**이므로 이 정밀도는 오직 **레이더 큐 + 요격기 유도**로만 확보해야 합니다.
짐벌 없이 sub-0.3°는 매우 도전적 → 현실적 대안:
1. **큐·유도 정밀도 극대화**(합성 σ<0.3° 목표) — 최우선 요구사항
2. **교전을 더 가까이 유도**해 분류 거리 단축(픽셀↑) — 단, 반응 시간과 상충 주의
3. **목표 P_negate를 짐벌 없는 상한에 맞춰 현실화**

화각은 ~1.7°로 고정하면 충분(튜닝 여지 작음).

## 4. 파라미터 그룹

- **위협**: RCS, 속도, 고도 AGL, 진입거리, 진입방위, 표적크기
- **레이더**: 기준 RCS/탐지거리, 최대 Pd, 전이 폭, 재방문 주기, 분류 시간, 분류기 상한
- **EO/IR**: 화각, 해상도, 센서폭, **요구 판별 수준**, 탐지/인식/식별 N50, 레이더 큐 오차, 요격기 지향 오차, 대기 시정
- **이팩터**: 페이로드(택일), 발사 지연, 순항속도, 최대교전거리, 발사대 거리,
  **단발 Pk·net / ·shotgun(독립 입력, 페이로드가 선택한 쪽만 P_kill에 사용 — 활성 강조 표시)**,
  사격 기회, 체공 시간, 여유 σ
- **C2**: 결심 지연, 결심 신뢰도
- **사이트**: keep-out 반경, 자산 위경도

## 5. 결과 읽기

- **교전 효과도**: P_negate/누수 + 교전 성립, 제약 단계 카드, 킬체인 막대, EO/IR 인식·획득 readout, 교전 기하 타임라인.
  해석식 ↔ **몬테카를로** 전환 가능.
- **방어 커버리지**: 360° 스윕 footprint 지도 + 평균 P_negate. (모델 회전대칭 → 전 방위 동일, 병목도 동일)
- **트레이드 스터디**: 파라미터 vs P_negate 1D/2D 스윕 + 민감도 토네이도.
- **스펙 역산**: 목표 P_negate를 만족하는 파라미터 임계값 역산.
- **시나리오 비교**: 현재(A) vs 프리셋/저장본(B) 지표 나란히 + Δ(개선=초록·악화=빨강).
- **파라미터 설명**: 전 파라미터 의미·값 출처 표 + 행별 "수식·그림".

## 6. 시나리오 운용

- **프리셋**: 소형 FPV(기본)·고속 고정익·저피탐 초소형·근거리 급습·안개 저시정·야간 EO 저하
- **저장/불러오기**: 현재 값을 이름 붙여 localStorage에 저장, 드롭다운에서 로드/삭제
- **A/B 비교**: 시나리오 비교 탭에서 B 선택

## 7. 입출력

- **CSV 저장/불러오기**: 열 = 구분·파라미터·key·값·단위·의미·값 출처·수식·이론 근거·모델 가정.
  첫 줄 `sep=,`로 Excel 열 밀림 방지, UTF-8 BOM으로 한글 정상. Excel에서 **값 열만** 수정 후 다시 불러오기.
- **⤓샘플**: 기본 시나리오 샘플 CSV 다운로드(포맷·근거 참조용).
- **JSON / 리포트(MD)**: 전체 결과+입력(JSON) / 사람이 읽는 리포트(MD, EO/IR 획득 섹션 + 파라미터 근거 부록 포함).

## 8. 몬테카를로 설계 — 어떤 변수에 오차가 들어가나

두 종류의 불확실성이 있습니다.

### 8.1 Aleatory(시행마다 물리적 변동) — 현재 MC가 난수화하는 입력

| 변수 | 분포 | 기본 오차 |
|---|---|---|
| 위협 속도 | 정규(승법) CV | 0.15 |
| RCS | 로그정규 σ | 0.4 |
| 진입 방위 | 균등 0–360° | on |
| 분류 시간 | 정규(가법) sd | 2 s |
| 결심 지연 | 정규(가법) sd | 4 s |
| 발사 지연 | 정규(가법) sd | 1 s |
| 요격기 지향 오차 | 정규(가법) sd | 0.15° |
| 대기 시정 | 정규(승법) CV | 0.25 |
| 위협 고도 | 정규(가법) sd | 40 m |
| 표적 크기 | 정규(승법) CV | 0.20 |
| 레이더 큐 오차 | 정규(가법) sd | 0.1° |
| 순항속도 | 정규(승법) CV | 0.05 |
| 사격 기회 수 | 정규(가법)·반올림 sd | 0.7 |

+ 킬체인 5게이트는 매 시행 **베르누이 결과**로 실현(확률→성공/실패).

> 모든 기본 오차값은 SME-VERIFY 플레이스홀더입니다. `DEFAULT_UNCERTAINTY`(montecarlo.ts)에서 조정.

### 8.2 미반영 → 반영으로의 차이 (정확히)

변수를 `sampleScenario`에 배선하면 매 시행 새 값을 뽑습니다. 이때 두 가지가 달라집니다:
- **시행별 P_negate 히스토그램 폭** ↑ (입력 변동이 분포에 나타남)
- **평균(mean) 이동** — 모델이 비선형/비대칭이면 평균 자체가 움직임.
  예: 고도(경사거리 볼록)·표적크기 변동은 불리한 쪽 페널티가 더 가팔라 **평균 P_negate를 끌어내림**
  (실측 예: 후보 반영 시 평균 37%→33%).

> 주의 — 도구의 **`ci95`는 "무력화 *분율*"의 몬테카를로 표본오차**(≈1.96·√(p(1−p)/n))로,
> 주로 **시행 수 n**이 지배합니다. 입력 변동을 늘려도 이 분율 CI 폭은 크게 안 변합니다
> (그건 시행별 P_negate **히스토그램**과 **평균**에 나타남). CI를 좁히려면 시행 수를 늘리세요.

위 표는 현재 반영된 aleatory 입력 전체입니다. 미반영이면 고정값이라 그 변수의 변동이 분포·평균에 0 기여(과신).

### 8.3 Epistemic(값 자체를 모름 — 플레이스홀더) — 현재 미반영, 실측 전까지 사실상 지배적

- **단발 Pk**, **N50(탐지/인식/식별)**, **기준 탐지거리**, **결심 신뢰도**, **분류기 상한**
- 이 값들은 "입력 필요" 상태라 불확실성이 큼. 정식 MC 설계 시 이들에 대한 **파라미터 사전분포**를 별도로 두는 것을 권장(aleatory와 분리).

### 8.4 주의 — 이중 계산

`여유 σ`(reach_margin_sigma_m)는 해석식에서 P_reach를 이미 연속화합니다. MC에서는 속도·타이밍
입력을 난수화해 여유가 또 흔들리므로 **부분 이중 계산**이 됩니다. 정식 MC에서는 (a) 여유 σ=0으로 두고
입력 난수가 도달 변동을 만들게 하거나, (b) σ를 "모델 외 잔여 지터"로만 해석하도록 정하세요.

## 10. 설계 결정·한계·가정

**확정 설계 결정**

- ⏳ **표적 크기(임계 치수)** — 대상 기종 미정. 값은 가정(참고 0.35m)이며, 인식·P_classify에 민감하므로 확정 시 재평가 필요.

**모델 한계·가정**
- 교전 closing 기하는 수평 반경(고도는 센싱에만 반영).
